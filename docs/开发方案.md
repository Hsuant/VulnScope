# VulnScope POC 管理系统 — 开发方案

> 版本：v2.0  |  日期：2026-08-13  |  状态：定稿

---

## 1. 项目概述

### 1.1 定位

VulnScope 是一套**以 POC（Proof of Concept，漏洞验证脚本/模板）为核心资产**的管理系统。当前阶段（v1）聚焦 **POC 的管理与持久化存储**，同时从第一天起为后续扩展模块预留标准化的插入位（插件槽）：

| 模块 | 当前状态 | 预留的接入点 |
|------|---------|-------------|
| POC 管理存储（CRUD / 搜索 / 导入导出 / 标签分类） | ✅ v1 实现 | — |
| POC 验证执行模块 | ⏳ 预留 | `verifier` 插件接口 + 异步任务队列 |
| AI 自动生成 POC 模块 | ⏳ 预留 | `source(generate)` 插件接口 + 生成任务 |
| 自动化爬取 POC 模块 | ⏳ 预留 | `source(crawl)` 插件接口 + 定时调度 |

### 1.2 设计原则

1. **核心稳定，插件即插即用**：核心只做"管理 + 存储 + 领域事件"，一切外部能力（验证、生成、爬取、新格式解析）以插件形式装载，核心代码零改动即可扩展。
2. **格式无关（Format-Agnostic）**：POC 内容可以是 nuclei YAML、pocsuite3 脚本、自研 JSON、任意脚本，系统不关心其内部语义，只做结构化管理与元数据封装。
3. **事件驱动**：核心发布领域事件（POC 创建/更新/删除、批量导入），插件通过事件总线订阅，实现模块间解耦联动。
4. **数据模型弹性**：用 JSON 扩展字段 + 稳定的核心字段，兼顾查询效率与扩展性。
5. **安全默认**：存储层对内容做完整性哈希、导入做格式校验与大小限制，审计留痕。

### 2.1 分层职责

| 层 | 职责 | 关键约束 |
|----|------|---------|
| API 层 | 路由、鉴权、参数校验、限流、错误码 | 不承载业务逻辑 |
| 服务层 | 业务用例编排、事务边界、领域事件发布 | 依赖插件接口而非具体实现 |
| 插件层 | 各扩展点实现 | 启动时加载进注册表，运行时仅可禁用，不可动态装卸 |
| 数据层 | ORM、迁移、存储 | 全部经 SQLAlchemy，禁止裸 SQL 拼接 |

## 5. 核心数据模型

### 5.1 设计总则

1. **枚举一律 VARCHAR + 应用层校验**：`severity` / `format` / `status` / `source` 均存字符串，合法值由 Pydantic `Literal` 或枚举定义，禁止 MySQL ENUM——插件新增格式（如 nuclei-yaml）无需 ALTER TABLE。
2. **命名标识不做全局唯一主键**：`poc.name` 是业务可读的参考字段，唯一约束为 `(name, source)`，去重的权威依据是 `content_hash`。
3. **CVE 与 POC 多对多**：通过 `poc_vuln` 关联表，方向自由。
4. **产品版本分离**：POC 不直接存版本号，通过 `poc_affected` 关联到 `product`，版本范围用 `version_start` + `version_end` + 边界类型表达，支持精确匹配。
5. **分类树形化**：`category` 从扁平枚举改为树形结构，支持 `web.framework.struts2` 层次路径，前缀搜索即可查询子树。
6. **标签命名空间**：`tag` 增加 `namespace` 字段，支持 `attack:rce`、`auth:unauth`、`impact:code-exec` 等结构化标签。
7. **内容不可变 + 版本快照**：`content` 更新即产生 `poc_version` 历史快照；`poc.version` 仅作乐观锁，不承担内容版本语义。
8. **弹性扩展位**：`extra_meta` JSON 为后续模块自由写入，不改表。

### 5.2 厂商-产品-组件体系

```
vendor（厂商）
├── id, name, slug UNIQUE, homepage, description
│
product（产品，如 Struts2、Exchange、WebLogic）
├── id, vendor_id FK, name, slug UNIQUE, category VARCHAR (web/server/framework/...),
│    homepage, description, logo, created_at, updated_at
│
component（子组件，可选细分，如 Struts2 Showcase Plugin）
  ├── id, product_id FK, name, slug UNIQUE, description
  └── created_at, updated_at
```

| 表 | 唯一约束 | 说明 |
|----|---------|------|
| `vendor` | `slug` | 厂商，如 `apache`、`microsoft`、`oracle` |
| `product` | `slug` | 产品，如 `struts2`、`exchange`、`weblogic` |
| `component` | `slug` | 子组件，如 `struts2-rest-plugin` |

### 5.3 POC 主表 `poc`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK, AUTO_INCREMENT | 内部主键 |
| `uuid` | CHAR(36) UNIQUE | 对外标识，跨环境稳定 |
| `name` | VARCHAR(128) | 业务名（如 `struts2-s2-045-rce`），不唯一 |
| `title` | VARCHAR(255) | 中文/显示标题 |
| `description` | TEXT | 漏洞描述 |
| `severity` | VARCHAR(16) INDEX | `info / low / medium / high / critical`（应用层校验） |
| `format` | VARCHAR(32) INDEX | `nuclei-yaml / json / pocsuite3 / raw-script`（应用层校验） |
| `language` | VARCHAR(32) | 脚本语言（raw-script 时有效） |
| `content` | LONGTEXT | POC 内容主体（模板/脚本） |
| `content_hash` | CHAR(64) INDEX | 对**归一化后内容**计算 SHA-256，用于去重与完整性校验 |
| `author` | VARCHAR(128) | 作者 |
| `source` | VARCHAR(32) INDEX | 主来源类型：`manual / imported / ai / crawler`（应用层校验） |
| `status` | VARCHAR(16) INDEX | `draft / active / disabled / archived`（应用层校验） |
| `version` | INT DEFAULT 1 | 乐观锁版本号（并发控制，不表示内容版本） |
| `extra_meta` | JSON | 扩展元数据，后续模块自由写入（验证结果、AI 参数等） |
| `created_by` / `updated_by` | BIGINT FK→user | 审计 |
| `created_at` / `updated_at` | DATETIME(3) | 时间戳 |

唯一约束：`UNIQUE(name, source)`；`UNIQUE(uuid)`。

### 5.4 版本影响范围 `poc_affected`

每条记录表示"该 POC 命中某个产品的一个版本区间"。一个 POC 可关联多个产品，一个产品可关联多个版本区间。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 主键 |
| `poc_id` | BIGINT FK→poc | POC |
| `product_id` | BIGINT FK→product | 产品 |
| `component_id` | BIGINT FK→component | 子组件（可选） |
| `version_start` | VARCHAR(32) | 起始版本号，如 `2.3.0` |
| `version_start_type` | VARCHAR(8) | `gte / gt / any`（大于等于 / 大于 / 任意） |
| `version_end` | VARCHAR(32) | 截止版本号，如 `2.3.31` |
| `version_end_type` | VARCHAR(8) | `lte / lt / any`（小于等于 / 小于 / 任意） |
| `version_expression` | VARCHAR(255) | 原始版本表达式，如 `>= 2.3.0, < 2.3.32`，供前端展示 |
| `created_at` | DATETIME(3) | 创建时间 |

**边界类型组合示例**：

| 语义 | version_start | version_start_type | version_end | version_end_type |
|------|--------------|-------------------|------------|-----------------|
| [2.3.0, 2.3.31] | 2.3.0 | gte | 2.3.31 | lte |
| ≤ 1.0.8 | — | any | 1.0.8 | lte |
| ≥ 3.0.0 | 3.0.0 | gte | — | any |
| (2.3.0, 2.5.0) | 2.3.0 | gt | 2.5.0 | lt |
| = 2.5.0 | 2.5.0 | gte | 2.5.0 | lte |
| 全部版本 | — | any | — | any |

| `id` | BIGINT PK | 主键 |
| `parent_id` | BIGINT FK→category | 父分类，NULL 为根节点 |
| `name` | VARCHAR(64) | 显示名，如 `Struts2`、`CMS` |
| `slug` | VARCHAR(128) UNIQUE | 路径标识，如 `web.framework.struts2` |
| `description` | TEXT | 描述 |
| `level` | INT | 层级深度，根为 0 |
| `sort_order` | INT | 排序权重 |

### 5.6 标签系统 `tag`

标签增加 `namespace` 字段，实现标签分组。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 主键 |
| `namespace` | VARCHAR(32) | 命名空间，如 `attack`、`auth`、`impact`、`layer` |
| `name` | VARCHAR(64) | 标签名，如 `rce`、`unauth` |
| `color` | VARCHAR(7) | 颜色，如 `#ff0000` |
| `description` | VARCHAR(255) | 描述 |

唯一约束：`UNIQUE(namespace, name)`。

**预置标签命名空间**：

| 命名空间 | 标签值 | 说明 |
|---------|--------|------|
| `attack` | `rce / sqli / xss / lfi / ssrf / ssti / file-upload / auth-bypass / idor / xxe` | 攻击类型 |
| `auth` | `unauth / user-auth / admin-auth` | 认证前提 |
| `impact` | `code-exec / info-disclosure / dos / priv-esc / file-read / rce` | 影响后果 |
| `layer` | `web / middleware / database / os / network / hardware / cloud / mobile` | 影响层面 |
| `type` | `poc / exploit / scanner / bruteforce` | POC 用途类型 |
| `status` | `verified / unverified / deprecated / draft` | 验证状态 |
| `lang` | `python / go / java / ruby / yaml / bash` | 开发语言 |
| `os` | `windows / linux / macos / multi` | 目标操作系统 |
| `protocol` | `http / https / tcp / udp / dns / smb / ldap / rmi` | 网络协议 |

### 5.7 POC 执行元信息 `poc_deployment`

供验证模块（v2）使用，描述 POC 的执行前置条件。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 主键 |
| `poc_id` | BIGINT FK→poc | POC |
| `attack_vector` | VARCHAR(32) | `network / adjacent / local / physical` |
| `auth_required` | BOOLEAN | 是否需要认证 |
| `auth_role` | VARCHAR(32) | `anonymous / user / admin` |
| `protocol` | VARCHAR(32) | 网络协议，如 `http / https / tcp / dns` |
| `default_port` | INT | 默认端口，如 80、443、8080、3306 |
| `requires_interaction` | BOOLEAN | 是否需要人工交互 |
| `safe_to_run` | BOOLEAN | 是否安全（不破坏目标） |
| `extra_meta` | JSON | 扩展元数据 |

### 5.8 其他关联表

| 表 | 关键字段 | 用途 |
|----|---------|------|
| `poc_version` | `id, poc_id FK, version_seq, content, content_hash, changed_by, changed_at` | 内容历史快照；`content` 变更时落地一条，`version_seq` 从 1 递增 |
| `poc_vuln` | `poc_id FK, vuln_id FK`（联合唯一） | POC↔CVE 多对多 |
| `vuln` | `id PK, cve_id UNIQUE, title, description, cvss, severity` | CVE 漏洞实体；`cve_id`（如 `CVE-2017-5638`）为业务主键查找字段 |
| `poc_tag` | `poc_id, tag_id`（联合唯一） | POC↔标签多对多 |
| `poc_category` | `poc_id, category_id`（联合唯一） | POC↔分类多对多 |
| `poc_source_record` | `id, poc_id, source_type, batch_id, source_url, ref_id, fetched_at, extra_meta JSON` | 来源溯源留痕；`batch_id` 记录一次抓取/生成的批次 |
| `poc_attachment` | `id, poc_id, file_name, file_path, file_type, size, sha256` | 附属文件（payload、参考脚本） |
| `user` | `id, username, password_hash, role, status` | 用户 |
| `role` | `id, name, permissions JSON` | 角色（RBAC） |
| `audit_log` | `id, user_id, action, resource_type, resource_id, detail JSON, ip, created_at` | 操作审计；`detail` 固定结构 `{before, after}` 摘要 |

### 5.9 版本范围查询引擎

POC 管理中最核心的操作：**给定产品 X 和版本 Y，命中哪些 POC？**

**版本号归一化**：

```python
def normalize_version(v: str) -> tuple[int, ...]:
    """2.3.15 → (2, 3, 15, 0)，补 4 段便于比较。"""
    parts = [int(x) for x in v.split(".")]
    while len(parts) < 4:
        parts.append(0)
    return tuple(parts)
```

**版本匹配算法**：

```python
class VersionRange:
    def __init__(self, start: str, start_type: str, end: str, end_type: str):
        self.start = Version(start) if start else None
        self.start_type = start_type  # gte / gt / any
        self.end = Version(end) if end else None
        self.end_type = end_type      # lte / lt / any

    def matches(self, v: Version) -> bool:
        if self.start_type == "gte" and not (self.start <= v):
            return False
        if self.start_type == "gt" and not (self.start < v):
            return False
        if self.end_type == "lte" and not (v <= self.end):
            return False
        if self.end_type == "lt" and not (v < self.end):
            return False
        return True
```

**业务查询 API**：
```
GET /api/v1/products/{slug}/pocs?version=2.3.15
```

服务层流程：查找产品 → 加载 `poc_affected` 关联 → 逐条 `matches()` 匹配 → 返回命中 POC 列表。

### 5.10 检索策略

- **产品检索**：`product.slug` 精确匹配，辅以 `product.name LIKE` 模糊。
- **版本检索**：经 `poc_affected → product` 关联，应用层版本匹配算法精确筛选。
- **分类检索**：`category.path LIKE 'web.framework.%'` 前缀匹配子树。
- **标签检索**：`tag.namespace:name` 精确匹配，支持多标签 AND 组合。
- **中文检索**：`title` / `description` 中文走 `LIKE %q%` + 索引，万级数据量毫秒级。
- **精确字段**：`severity` / `status` / `source` / `format` 走等值 + 组合条件索引。
- **CVE 检索**：经 `poc_vuln → vuln.cve_id` 关联查询。
- **数据量增长到十万级**后再评估 OpenSearch / MySQL `ngram` 全文索引，v1 不引入。

## 6. 标准 POC 模板（规范）

### 6.1 两层结构

系统内存在两种"POC 标准形态"，职责不可混用：

| 形态 | 性质 | 用途 |
|------|------|------|
| `NormalizedPoc`（IR） | 进程内中间表示，Python 数据结构 | 插件 ↔ 存储管道之间的稳定契约，任何来源的数据必须先归一化到此形态 |
| **Nuclei 模板（标准载体）** | 对外的完整 Nuclei YAML 模板（ProjectDiscovery 规范） | 用户编写、存储、导入导出的标准载体；`NormalizedPoc.content` 即完整模板文本 |

**Nuclei 是唯一第一方格式**：标准模板即完整 Nuclei YAML，兼容项目生态（projectdiscovery/nuclei-templates）中数千条现成模板的直接导入，v2 验证模块用 nuclei 引擎原生执行，无需任何格式转换。其他格式（如 pocsuite3）作为历史数据兼容格式，经 `Parser` 插件归一化（非纯透传，需产出合法 Nuclei 模板或降级为 `raw-script`）。

### 6.2 模板结构

标准模板遵循 ProjectDiscovery 模板语法，完整参考模板见 `docs/poc-template/nuclei-reference.yaml`，顶层结构：

```yaml
id:                  # 必填，唯一标识，业务命名规范同 §8.2 查询用的 name
info:                # 必填，元数据块
  name:              # 模板名
  author:            # 作者
  severity:          # info/low/medium/high/critical（入库映射到 poc.severity）
  description:       # 描述（入库映射到 poc.description）
  remediation:       # 修复建议
  reference:         # 参考链接数组（→ poc_source_record.reference）
  classification:    # CVE / CWE / CVSS（cve-id → poc_vuln 关联）
    cve-id: [CVE-2017-5638]
    cwe-id: [CWE-917]
    cvss-metrics: /CVSS:3.0/AV:N/.../C:H/I:H/A:H
    cvss-score: 10.0
  metadata:          # 厂商/产品元数据
  tags:              # 逗号分隔，入库拆分写入 poc_tag（app 按需取用）
  max-request:       # 单目标最大请求数限制（验证模块用）

# 请求块（至少一种；v2 验证引擎原生执行）
http: [ ]            # HTTP 请求（header/body/matchers/extractors/payloads）
dns: [ ]             # DNS 查询
network: [ ]         # 原始 TCP/UDP
ssl: [ ]             # TLS 证书
headless: [ ]        # 无头浏览器（JS 渲染）
websocket: [ ]       # WebSocket
file: [ ]            # 文件读取
code: [ ]            # OS 命令执行（nuclei v3, 需要 -code 许可）

# 共享组件
variables: { }       # 模板级变量
stop-at-first-match: true
```

### 6.3 与核心数据模型的字段映射

| Nuclei 模板位置 | 库字段 | 说明 |
|------|---------|------|
| `id` | `poc.name` | 唯一业务名；`UNIQUE(name, source)` |
| `info.name` | `poc.title` | 显示标题 |
| `info.description` / `info.remediation` | `poc.description` | 描述拼接（remediation 存 `extra_meta`） |
| `info.author` | `poc.author` | 作者 |
| `info.severity` | `poc.severity` | 级别 |
| `info.classification.cve-id` | `poc_vuln` 关联 | 多个 CVE 逐条关联 |
| `info.tags` | `poc_tag` | 拆分入库 |
| `info.metadata` | `extra_meta` | 厂商/产品等元数据透传 |
| `info.reference` | `poc_source_record.reference` | 溯源链接 |
| 全模板文本 | `poc.content` | 原样存储（`lint` 规范化格式后落库） |
| — | `poc.format = "nuclei-yaml"` | 标准模板恒为 nuclei-yaml |

### 6.4 模板规范约束（validate()）

入库前强制校验，违反即拒绝：

1. **结构合法性**：YAML 可解析、顶层为映射、`id` 与 `info` 存在且类型正确。
2. **字段约束**：`id` 匹配 `^[a-z0-9.-]+$`；`severity` 在合法枚举内；`info.classification.cve-id` 若存在须匹配 `^CVE-\d{4}-\d{4,}$`。
3. **请求块完整性**：至少存在一种请求块（http/dns/network/ssl/headless/websocket/file/code）；`http` 块中 `method` + `path`/`raw` 必须成对出现。
4. **matchers 语义**：`matchers.type ∈ {word, regex, status, code, size, binary, dsl, condition}`；无 matchers 且有 suppress 条件的按规范放行。
5. **禁止执行型风险字段**（v1 拦截，白名单外拒绝）：`headless`、`code` 块 v1 一律拒绝入库（无沙箱执行环境），属 v2 验证模块白名单能力；`http.unsafe` + `raw` 需二次人工确认标记 `extra_meta.unsafe_ack = true`。

### 6.5 归一化规则（Raw → IR → 存储）

1. `Parser` 插件把任意原始输入解析为 `NormalizedPoc[]`（IR）：`nuclei-yaml` 直接解析元数据；其他格式尽力转换（元数据不齐时 `severity=info`、`category=other`，内容以合法模板或 `raw-script` 落库）。
2. 服务层对模板执行 **lint 规范化**：统一换行（`\n`）、去尾随空白、键顺序稳定（`id → info → 请求块`）。
3. 对**规范化后文本**计算 `content_hash`（SHA-256），作为去重唯一键。
4. 校验：`validate()`（§6.4）全绿才入库。
5. 去重命中 → 返回 `DUPLICATE` 结果（不覆盖，由调用方决定是否更新版本）；未命中 → 事务入库 + 落 `poc_version` 首版本 + 发布事件。

### 6.6 各格式适配

| `content.format` | v1 状态 | 内容形态 |
|------|---------|---------|
| `nuclei-yaml` | ✅ 原生支持（标准模板） | 完整 Nuclei 模板文本，v2 原生可执行 |
| `json` | ⏳ 兼容导入 | 自研结构化 JSON，Parser 转换后落库为标准模板 |
| `pocsuite3` | ⏳ 兼容导入 | Python 脚本，Parser 提取元数据，内容降级 `raw-script` |
| `raw-script` | ✅ 存储透传 | `language` + 源码，仅文本存储，无执行能力 |

> 标准形态恒定是 Nuclei 模板——导入的任意格式经 Parser 归一化后，存储层保存的都是合法模板（`raw-script` 仅作为无模板等效物的兜底）。

## 7. 模块可插拔设计

### 7.1 插件槽（Extension Points）一览

| 插件槽 | 接口 | v1 内置实现 | 后续注入 |
|--------|------|------------|---------|
| `Parser` | `parse(raw, format) -> NormalizedPoc[]` + `validate()` | nuclei YAML 解析器（标准模板） | 其他厂商/历史格式转换器 |
| `Source` | `fetch(params) -> NormalizedPoc[]` | manual（手动录入） | AI 生成、GitHub 爬取、CVE 同步 |
| `Verifier` | `verify(poc, target, options) -> VerifyResult` | 无（占位） | 内置 HTTP 验证引擎、nuclei 桥接 |
| `Exporter` | `export(pocs, target_format) -> bytes` | JSON 导出 | nuclei/pocsuite3 模板导出 |
| `EventConsumer` | `handle(event)` | 审计日志消费 | 验证自动触发、AI 生成后通知 |

### 7.2 插件生命周期

```
发现 (discover) → 加载 (load) → 注册 (register) → 启用 (enable) → 调用 (invoke) → 停用 (disable)
```

- **发现机制**：两路并用——
  1. Python 标准 `importlib.metadata.entry_points(group="vulnscope.plugins")`，支持第三方包接入；
  2. 项目内 `plugins/` 目录 + 约定式 `plugin.py` 模块。
- **注册表**：`PluginRegistry` 维护 `{slot: {name: PluginInstance}}`，启动时校验接口契约（`isinstance` / ABC），契约不符拒绝加载并告警。
- **生命周期边界**：插件在**启动时扫描加载**，运行时可整槽禁用；v1 不提供运行时动态装卸（需要独立进程隔离，属 v2+ 能力）。
- **去耦调用**：服务层只依赖接口（如 `Source.fetch()`），不 import 具体插件类；插件缺失时返回明确错误码 `PLUGIN_NOT_AVAILABLE`。

### 7.3 接口契约（Python）

```python
# plugins/base.py
class NormalizedPoc(BaseModel):
    """核心与插件之间的稳定中间表示（IR）。"""
    name: str
    title: str | None = None
    description: str | None = None
    author: str | None = None
    source: str = "manual"
    category: str = "other"
    severity: str = "info"
    content: str
    format: str
    language: str | None = None
    cve_ids: list[str] = []
    tags: list[str] = []
    references: list[str] = []
    extra_meta: dict = {}

    def validate(self) -> list[str]:
        """结构自检，返回错误列表（空列表 = 合法）。AI 生成模块复用此管道。"""

class PocSource(ABC):
    """POC 来源插件：手动录入 / AI 生成 / 爬取统一走此接口。"""
    name: str
    version: str

    @abstractmethod
    def fetch(self, params: dict) -> list[NormalizedPoc]:
        """获取/生成一批规范化 POC 数据。"""

class PocParser(ABC):
    """格式解析插件。"""
    supported_formats: set[str]

    @abstractmethod
    def parse(self, raw: str | bytes) -> list[NormalizedPoc]:
        """把原始内容解析为规范化 POC。"""

class PocVerifier(ABC):
    """验证引擎插件（v2 实现）。"""
    @abstractmethod
    def verify(self, poc, target: str, options: dict) -> VerifyResult:
        """对目标执行 POC 验证，返回结构化结果。"""
```

> 接口方法统一命名 `fetch()` / `parse()` / `verify()`；插件实例以 `name` 区分（`manual`、`ai_generate`、`github`），不通过方法名表达来源实现方式。

### 7.4 事件总线

```python
# core/events.py
class EventTypes(str, Enum):
    POC_CREATED = "poc.created"
    POC_UPDATED = "poc.updated"
    POC_DELETED = "poc.deleted"
    POC_STATUS_CHANGED = "poc.status_changed"
    POC_VERSION_CREATED = "poc.version_created"
    BATCH_IMPORTED = "poc.batch_imported"

class EventBus:
    def publish(self, event: DomainEvent) -> None: ...
    def subscribe(self, event_type: str, handler) -> None: ...
```

- **v1 事件集收敛**：仅暴露 `poc.*` 与 `batch_imported`；验证、AI、爬取相关事件（`verify.requested`、`source.fetched`）随对应模块引入，不预置空壳事件。
- **消费者契约**：订阅者必须快速返回（纯内存操作），不得阻塞发布方；发布采用 `asyncio.create_task` 异步派发，发布方不等待消费结果。
- v1 内置消费者：`AuditLogConsumer`（审计留痕，消费 `poc.*` 与 `batch_imported`）。
- 事件携带 `event_id`、`aggregate_id`、`occurred_at`、payload，为将来切换 MQ（RabbitMQ/Kafka）保留兼容字段。

### 7.5 导入管道（Import Pipeline）

```
文件/URL/文本 → 格式嗅探(FormatDetector) → 分发到对应 Parser 插件
    → 归一化 NormalizedPoc[] → 规范化+hash → validate() → 去重(sha256)
    → 事务入库（含 poc_version 首版本）→ 发布 BATCH_IMPORTED 事件
```

- 格式嗅探：magic bytes / 扩展名 / YAML 头 / JSON 结构启发式判定。
- 失败隔离：单条 POC 解析失败不影响整批，返回逐条错误报告。

| 方面 | 措施 |
|------|------|
| 内容安全 | POC 是脚本/模板，存储侧一律按纯文本处理，服务端**永不执行**；执行能力只存在于 v2 验证插件（沙箱/容器隔离，另行设计） |
| 上传安全 | 导入限大小 10MB、限制扩展名、MIME 校验、内容嗅探防伪装 |
| 注入防护 | 全参数化查询（SQLAlchemy）、Pydantic 严格校验、无模板注入 |
| 认证授权 | JWT + RBAC + 密码 bcrypt；管理接口强制鉴权 |
| 审计 | 写操作全量 `audit_log`，含 IP 与 `{before, after}` 摘要 |
| 部署 | 容器运行时非 root、DB 最小权限账号、敏感配置走环境变量/密钥管理 |

## 12. 工程质量

- **单测**：服务层 + 插件契约（`pytest`）。
- **集成测试**：SQLite 内存跑 CRUD/导入管道；MySQL 专属特性（JSON、索引）用 Docker 单例验证。
- **契约测试**：API 响应结构（Pydantic schema 快照）+ POC 模板 JSON Schema 校验（`jsonschema`）。
- **性能基准**：万级 POC 数据量下列表接口 P95 < 200ms；批量导入 1000 条 < 5s。
- **CI**：GitHub Actions（lint + 单测 + 集成 + 构建镜像）。
- **代码规范**：Ruff（lint）+ Black（format）+ mypy（类型检查），pre-commit 钩子。

## 13. 开发里程碑

| 里程碑 | 内容 | 验收标准 |
|--------|------|---------|
| **M1 骨架**（1 周） | 项目脚手架、配置分层、DB 迁移、鉴权、统一异常 | `pytest` 全绿，Swagger 可跑通 login+CRUD |
| **M2 核心存储**（1 周） | POC/Vuln/PocVuln/Tag/PocVersion 模型、CRUD API、过滤排序分页、搜索 | 核心 API 用例通过 |
| **M3 插件框架**（1 周） | 注册表、事件总线、Parser/Source 槽、JSON 解析器、模板 Schema 校验、审计消费 | 插件契约单测；手动导入走通全管道 |
| **M4 导入导出**（3 天） | 导入向导 API、格式嗅探、去重、导出 JSON | 批量导入 1000 条 < 5s |
| **M5 前端**（2 周） | 列表/详情/导入/标签/插件面板/系统页 | 端到端流程可用 |
| **M6 收尾**（3 天） | Docker Compose、种子数据、文档、压测 | 一键 `docker compose up` 可运行 |

总计约 5~6 周（单人后端+前端）。M1~M3 测试先行，M5 前端与 M4 并行。
