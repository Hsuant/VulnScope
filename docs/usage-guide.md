## 1. 概述

VulnScope 是一套以 POC（Proof of Concept，漏洞验证脚本）为核心资产的管理系统。本说明书聚焦两个核心操作：**新建 POC** 和 **标签管理**。

### 1.1 角色说明

| 角色 | 权限 | 适用人员 |
|------|------|---------|
| 查看者（viewer） | 查看 POC、标签、插件状态 | 安全运营、审计人员 |
| 编辑者（editor） | POC 增删改、导入导出、标签管理 | 安全研究员、渗透测试 |
| 管理员（admin） | 用户管理、审计日志、所有编辑权限 | 系统管理员 |

> 新建 POC 和标签管理需要 **editor 或 admin** 角色。

## 3. 新建 POC 详细指南

### 3.1 进入新建页面

点击侧边栏 **POC 管理 → 新建 POC**，或点击 POC 列表页右上角的「新建 POC」按钮。

页面分为左右两栏：

- **左栏**：基本信息表单 + 关联信息 + 受影响版本
- **右栏**：POC 内容编辑区（支持表单构建和源码两种模式）

### 3.2 填写基本信息

#### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 名称 | 是 | POC 业务标识名，以字母、数字或汉字开头，允许字母、数字、汉字、空格、点、连字符 | `struts2-s2-045-rce` |
| 标题 | 否 | 中文或显示标题，用于列表和搜索 | `Apache Struts2 S2-045 远程代码执行` |
| 严重级别 | 是 | 信息/低危/中危/高危/严重 | `严重` |
| 状态 | 是 | 草稿/已启用/已禁用/已归档 | `草稿` |
| 来源 | 是 | 手动录入/导入/AI 生成/爬取，会写入源码 metadata | `手动录入` |
| 格式 | 是 | POC 格式，决定右栏编辑模式，会写入源码 metadata | `Nuclei YAML` |
| 作者 | 否 | 作者名称或团队名 | `security-team` |
| 语言 | 否 | 脚本语言（格式为原始脚本时必填） | `python` |

#### 名称命名规范

```
格式: [vendor]-[product]-[vuln-type]-[optional-suffix]

示例:
  apache-struts2-rce
  thinkphp5-sql-injection
  cve-2024-12345
  fortigate-sslvpn-bypass
```

名称亦允许大写字母、汉字与空格，便于直接采用漏洞标题作为标识，例如 `n8n Unauthenticated Workflow RCE`。首字符仍须为字母、数字或汉字，避免以空格或标点开头。

### 3.3 填写关联信息

#### CVE 编号

在 CVE 编号输入框中输入标准 CVE 编号，回车确认。支持多条：

- `CVE-2024-12345`
- `CVE-2024-67890`

系统会在 CVE 漏洞库中创建或关联对应记录。

#### CNVD 编号

输入 CNVD/CNNVD 编号，回车确认，支持多条，例如 `CNVD-2024-12345`。该编号随 POC 一并保存，并在详情页展示。

#### FOFA 语法

填写资产探测 FOFA 查询语法，用于关联资产测绘数据，例如 `app="Apache-Struts2"`。填写后会写入生成源码的 `info.metadata.fofa`。

#### Shodan 语法

填写资产探测 Shodan 查询语法，例如 `http.favicon.hash:-831756631`。填写后会写入生成源码的 `info.metadata.shodan`。

#### 参考链接

逐条录入漏洞参考链接，每条包含 URL 与可选标题，适合收录漏洞公告、补丁地址、分析文章等。链接列表会写入生成源码的 `info.reference`。

#### 标签

从已有标签中选择，支持多选。标签按命名空间分组展示，方便快速筛选。

如果所需标签不存在，可先切换到标签管理页面创建（详见 [标签管理](#4-标签管理)），或让管理员预先创建好常用标签。

#### 描述

自由文本描述漏洞信息，包括漏洞原理、影响范围、利用条件等。

### 3.4 配置受影响版本

填写该 POC 适用的版本区间，每条包含起始与截止版本及其比较符：

| 字段 | 说明 | 示例 |
|------|------|------|
| 起始版本 | 受影响起点 | `1.0.0` |
| 起始操作符 | 起始边界关系（`>=` / `>`） | `>=` |
| 截止版本 | 受影响终点 | `1.121.0` |
| 截止操作符 | 截止边界关系（`<=` / `<`） | `<=` |

某一侧留空表示该侧不限定。版本区间会写入生成源码的 `info.metadata.affected`，形如 `>= 1.0.0 ~ <= 1.121.0`。

### 3.5 编辑 POC 内容

这是最核心的部分。编辑方式取决于所选格式：

#### Nuclei YAML 格式（推荐）

Nuclei 是 ProjectDiscovery 开发的模板扫描引擎，是业界最广泛使用的 POC 格式之一。VulnScope 为 Nuclei YAML 格式提供**表单构建**和**源码**两种编辑模式。

##### 表单构建模式

选择「Nuclei YAML」格式后，右栏默认进入表单构建模式。通过可视化表单填写协议参数，系统自动生成 YAML 源码。

**第一步：选择协议**

| 协议 | 适用场景 |
|------|---------|
| HTTP | Web 漏洞检测（最常用，支持 GET/POST 等） |
| TCP | 网络协议级漏洞检测（如 Redis 未授权） |
| Network | 原始 TCP，支持 TLS 加密与 SNI |
| WebSocket | WebSocket 协议漏洞检测 |
| DNS | DNS 查询类漏洞检测（如域名劫持） |

**第二步：配置请求**

HTTP 协议需要配置：

| 字段 | 说明 | 示例 |
|------|------|------|
| 请求方法 | GET / POST / PUT / DELETE 等 | `GET` |
| 请求路径 | 每行一个，支持 Nuclei 变量 | `{{BaseURL}}/admin` |
| 请求头 | 自定义 HTTP 请求头 | `Content-Type: application/json` |
| 请求体 | POST 请求体内容 | `{"cmd":"id"}` |

TCP 协议需要配置：

| 字段 | 说明 |
|------|------|
| 主机/输入 | 目标主机或输入数据，每行一个 |
| 端口 | 目标端口号 |
| 发送数据 | 需要发送的原始数据（支持 Hex 编码） |
| 读取字节数 | 预期读取的响应长度 |

Network 协议需要配置：

| 字段 | 说明 |
|------|------|
| 主机/输入 | 目标主机或输入数据，每行一个 |
| 端口 | 目标端口号 |
| 发送数据 | 原始数据（支持 Hex 编码） |
| 读取字节数 | 预期读取的响应长度 |
| TLS 加密 | 是否启用 TLS |
| TLS SNI | 服务器名称指示，如 `example.com` |

WebSocket 协议需要配置：

| 字段 | 说明 |
|------|------|
| URL | WebSocket 地址，如 `wss://example.com/ws` |
| 方法 | 请求方法 |
| 请求头 | 自定义请求头 |
| 消息体 | 发送的消息内容 |
| 仅读取一次 | 开启后只读取一次响应，不等待后续消息 |

DNS 协议需要配置：

| 字段 | 说明 |
|------|------|
| 域名 | 查询域名（支持 `{{FQDN}}` 变量） |
| 查询类型 | A / AAAA / CNAME / MX / TXT / NS |

**第三步：配置匹配规则**

匹配规则用于判断目标是否存在漏洞。至少需要配置一条有效规则。

| 匹配类型 | 说明 | 示例 |
|---------|------|------|
| 关键词 | 在响应中搜索特定字符串 | `root:x:0:0`、`admin` |
| 正则 | 正则表达式匹配 | `(uid|gid)=\d+` |
| 状态码 | 匹配 HTTP 状态码 | `200`、`302` |
| DSL | 表达式匹配，可引用提取器名称 | `response.status == 200` |

**匹配条件**：同一规则内多条表达式时，可选择 AND（全部满足）或 OR（满足任一）关系。多个匹配器之间默认按 OR 关系组合。

**第四步：配置提取器（可选）**

提取器用于从响应中抽取数据，可供后续请求或 DSL 匹配引用。每条提取器包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| 类型 | regex / dsl / json / kval / xpath | `regex` |
| 名称 | 提取结果名，供 DSL 引用 | `b64` |
| 匹配部位 | all / body / header（可留空） | `body` |
| 分组 | 正则分组序号（仅 regex） | `1` |
| 表达式 | 逐行填写，按类型输出为对应字段 | |
| 仅内部使用 | 结果不输出，仅供 DSL 引用 | 开 |

典型用法：先用 regex 提取一段 Base64，再用 dsl 解码并提取版本号，最后在匹配器中通过版本名引用：

```yaml
extractors:
  - type: regex
    name: b64
    regex:
      - '<meta name="n8n:config:sentry" content="([A-Za-z0-9+/=]+)"'
    internal: true
  - type: dsl
    name: version
    dsl:
      - 'base64Decode(b64).bsubmatch("n8n@(?P<version>[0-9.]+)")["version"]'
    internal: true
```

匹配器中即可引用 `version`：

```yaml
matchers:
  - type: dsl
    dsl:
      - "response.status == 200"
      - "versionCompare(version, '<', '1.121.0')"
    condition: and
```

**第五步：关联信息写入源码**

关联信息中的参考链接、FOFA 语法、Shodan 语法、受影响版本以及来源、格式，会一并写入生成源码：参考链接写入 `info.reference`，其余写入 `info.metadata`，保证导出的模板自包含、可直接用于扫描引擎。

##### 源码模式

点击「源码」切换按钮，可直接编辑 Nuclei YAML 原始内容，适合熟悉 Nuclei 语法的用户。

Nuclei 模板基本结构：

```yaml
id: example-poc

info:
  name: Example Vulnerability
  author: security-team
  severity: high
  description: "漏洞描述"
  tags: rce,example
  reference:
    - https://example.com/advisory
  metadata:
    fofa: app="Example"
    shodan: http.component:"example"
    source: manual
    format: nuclei
    affected:
      - ">= 1.0.0 ~ <= 2.0.0"

http:
  - method: GET
    path:
      - "{{BaseURL}}/vulnerable-path"
    headers:
      User-Agent: "Mozilla/5.0"
    matchers:
      - type: word
        part: body
        words:
          - "vulnerable_string"
        condition: and
```

> **提示**：在源码模式下编辑后，切回表单构建模式时会自动解析回填协议、请求、匹配器与提取器。但高级语法（如 raw 请求、多阶段交互）可能无法完全还原，建议在源码模式下集中编辑此类内容。

#### 其他格式

| 格式 | 编辑模式 | 说明 |
|------|---------|------|
| Nuclei YAML | 表单构建 + 源码 | 推荐，功能最完整 |
| JSON | 表单构建 + 源码 | 自研结构化格式 |
| Pocsuite3 | 仅源码 | Python 脚本格式 |
| 原始脚本 | 仅源码 | 任意语言脚本 |

### 3.6 保存 POC

点击右上角「保存」按钮，系统会：

1. 校验名称、严重级别、状态等必填字段
2. 校验表单构建模式下至少有一条有效匹配规则
3. 校验当前协议下必要的请求字段已填写
4. 检查内容是否重复（基于 SHA-256 内容哈希）
5. 检查名称在相同来源下是否唯一
6. 创建 POC 记录并自动生成首条版本快照

保存成功后自动跳转到 POC 详情页。

### 3.7 POC 状态流转

POC 有四种状态，流转规则如下：

```
草稿 ──→ 已启用 ←── 已禁用
  │         │         │
  │         └──→ 已归档 ←─┘
  │                    │
  └──────────→ 已启用 ←─┘
```

- **草稿**：初始状态，内容未完善
- **已启用**：验证通过，可投入使用
- **已禁用**：存在问题或不再推荐使用
- **已归档**：历史存档，不再维护

状态流转会记录到审计日志。

### 3.8 版本管理

每次保存内容时，系统保留一份版本快照。在详情页可查看版本历史：

- 每条版本记录包含：版本序号、内容哈希、保存时间
- 每次内容保存后版本号自动递增
- 通过版本历史可追溯 POC 演进过程

### 3.9 克隆 POC

在详情页点击「克隆」按钮，输入新名称，可快速复制现有 POC：

- 克隆内容包括：内容、标签、CVE 关联
- 新 POC 状态恒为 `草稿`
- 适合基于已有模板创建变体

## 4. 标签管理

### 4.1 标签体系

VulnScope 的标签采用**命名空间 + 标签名**的双层结构：

```
[命名空间]:[标签名]

示例:
  attack:rce           # 攻击类型：远程代码执行
  attack:sql-injection # 攻击类型：SQL 注入
  auth:bypass          # 认证：绕过
  impact:info-leak     # 影响：信息泄露
  oss:apache           # 组件：Apache
  language:python      # 语言：Python
```

### 4.2 进入标签管理

点击侧边栏「标签管理」，进入标签管理页面。页面按命名空间分组展示：

```
命名空间: attack
├── rce                 3 POC
├── sql-injection       2 POC
├── xss                 5 POC
└── lfi                 1 POC

命名空间: oss
├── apache              4 POC
├── nginx               2 POC
├── thinkphp            3 POC
└── wordpress           6 POC
```

### 4.3 新建标签

点击「新建标签」按钮，弹出对话框：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 命名空间 | 是 | 标签分类，选择已有或输入新名称 | `attack` |
| 标签名 | 是 | 标签名称 | `rce` |
| 颜色 | 否 | 标签显示颜色，便于视觉区分 | `#4a8cba` |
| 描述 | 否 | 标签说明 | `远程代码执行漏洞` |

**命名空间建议：**

| 命名空间 | 用途 | 标签示例 |
|---------|------|---------|
| `attack` | 攻击类型 | `rce`, `sql-injection`, `xss`, `ssrf`, `lfi` |
| `auth` | 认证相关 | `bypass`, `weak-password`, `oauth` |
| `impact` | 漏洞影响 | `info-leak`, `dos`, `privilege-escalation` |
| `oss` | 开源组件 | `apache`, `nginx`, `tomcat`, `wordpress` |
| `vendor` | 厂商 | `microsoft`, `cisco`, `vmware` |
| `language` | 脚本语言 | `python`, `go`, `ruby` |
| `severity` | 严重程度标记 | `critical`, `high`, `medium` |
| `status` | 状态标记 | `verified`, `unverified`, `deprecated` |

### 4.4 编辑标签

点击标签行可编辑：

- 编辑命名空间
- 编辑标签名
- 选择颜色
- 编辑描述

> 注意：编辑标签名或命名空间时，所有关联该标签的 POC 会自动同步关联关系。

### 4.5 删除标签

点击「删除」按钮可删除标签，已关联的 POC 不会受影响（仅解除关联关系）。

> 删除不可恢复，建议先确认标签未被重要 POC 使用。

### 4.6 标签的最佳实践

**方式一：按攻击类型组织（推荐）**

```
attack:rce
attack:sql-injection
attack:xss
attack:ssrf
attack:lfi
attack:file-upload
attack:auth-bypass
```

适用于渗透测试团队，按漏洞利用方式快速检索。

**方式二：按受影响组件组织**

```
oss:apache
oss:nginx
oss:tomcat
oss:jenkins
vendor:fortinet
vendor:cisco
```

适用于资产管理团队，按组件维度跟踪漏洞覆盖。

**方式三：按项目或阶段组织**

```
project:red-team-2024
project:penetration-test
status:verified
status:in-progress
```

适用于大型项目，按项目阶段跟踪 POC 进展。

## 5. POC 导入导出

### 5.1 导入 POC

进入「POC 管理 → 导入 POC」，支持两种方式：

**上传文件模式**：

- 支持拖拽或点击上传
- 支持批量多文件
- 单文件限制 10MB
- 支持格式：`.yaml` / `.yml` / `.json` / `.py` / `.go` / `.txt`

**粘贴文本模式**：

- 直接粘贴 POC 内容
- 支持多模板（多个 YAML 文档用 `---` 分隔）
- 自动格式识别

导入时可选配置：

| 配置 | 说明 | 默认值 |
|------|------|--------|
| 来源标记 | 标记导入来源 | `导入` |
| 默认状态 | 导入后的 POC 状态 | `草稿` |

### 5.2 导出 POC

在 POC 列表页勾选需要导出的 POC，点击「导出」：

| 导出格式 | 说明 | 适用场景 |
|---------|------|---------|
| JSON | 包含完整元数据（名称、标题、标签、CVE 等） | 数据备份、迁移 |
| Nuclei YAML | 纯模板文本（多个模板用 `---` 分隔） | 直接用于 Nuclei 引擎扫描 |

### 5.3 批量操作

在 POC 列表页勾选多条 POC 后，可进行：

- **批量删除**：一次性删除多个 POC
- **批量设置状态**：一次性设置多个 POC 的状态
- **批量导出**：将多个 POC 导出为同一份文件

## 6. CVE 漏洞库

CVE 漏洞库集中维护漏洞元数据，与 POC 通过 `cve_id` 多对多关联。POC 导入时若解析到 CVE 编号，会自动创建或补充对应的 CVE 记录；也可在此手动新建、编辑或批量导入。

### 6.1 CVE 列表

进入「CVE 漏洞库 → 列表」，页面提供：

- **搜索**：按 CVE 编号或标题模糊匹配
- **级别筛选**：按严重级别（信息/低危/中危/高危/严重）筛选
- **表格列**：CVE 编号、标题、级别（彩色徽标）、CVSS 评分、POC 数、更新时间、操作
- **行点击**：单击任意数据行（勾选列与操作列除外）直接进入 CVE 详情页
- **详情按钮**：操作列「详情」同样进入详情页
- **批量删除**：勾选多条后批量删除（editor/admin）

### 6.2 CVE 详情页

详情页采用单栏分区布局，自上而下：

| 分区 | 内容 |
|------|------|
| 顶部指标条 | 严重级别徽标、CVSS 评分（按级别着色，附版本号）、厂商、关联 POC 数（可点击跳转）、更新时间 |
| CVSS 指标向量 | 原始向量串 + 「复制向量」按钮 + 分解后的指标 chips（攻击向量/复杂度/权限/交互/范围/机密性/完整性/可用性，中文标注） |
| 漏洞描述 | 自由文本，支持 Markdown 渲染 |
| 受影响产品 | 表格：厂商 / 产品 / 版本区间（含/不含边界） |
| 修复建议 | 双卡片：官方补丁（绿）、临时方案（橙），均支持 Markdown 渲染 |
| 参考链接 | 可点跳转的链接列表，含标签与 host 副标注 |

操作区按钮：

- **关联 POC**：查询该 CVE 关联的首个 POC 并直达其详情页；无关联时提示
- **编辑**（editor/admin）：跳转编辑页
- **删除**（editor/admin）：确认后删除并返回列表

### 6.3 新建 / 编辑 CVE

新建与编辑共用同一表单，区别在于：

- **新建**：CVE 编号可编辑，须匹配 `CVE-YYYY-NNNNN`，重复时后端返回 409
- **编辑**：CVE 编号只读（漏洞标识不可改），其余字段覆盖式更新（传空值即清空）

表单字段：

| 字段 | 说明 |
|------|------|
| CVE 编号 | 新建态可填，编辑态只读 |
| 标题 | 漏洞标题 |
| 厂商 | 受影响软件的开发厂商 |
| 严重级别 | info/low/medium/high/critical，可留空 |
| CVSS 评分 | 0–10，精度 0.1 |
| CVSS 向量 | 如 `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H` |
| 描述 | 支持 Markdown |
| 受影响产品 | 动态卡片：厂商、产品、精确版本、起始版本（含/不含）、结束版本（含/不含），可增删 |
| 官方补丁 / 临时方案 | 两段 Markdown 文本 |
| 参考链接 | 动态行：URL + 标签（可选），可增删，空 URL 自动剔除 |

底部操作栏贴底固定，「取消」返回，「保存」跳详情页。新建态额外提供「保存并继续」，创建后清空表单留在本页，便于批量录入。

### 6.4 导入 CVE

进入「CVE 漏洞库 → 导入 CVE」，支持文件上传与文本粘贴两种方式，单文件限 10MB，可批量多文件。

**支持格式**：

| 格式 | 扩展名 | 结构 |
|------|--------|------|
| JSON | `.json` | 单对象或对象数组 |
| JSONL | `.jsonl` | 每行一个 JSON 对象，空行跳过 |
| YAML | `.yaml` / `.yml` | 单文档对象、对象列表或多文档（`---` 分隔） |
| Markdown | `.md` | front-matter（`---` 包裹的 YAML 头）取结构化字段，正文作为描述 |

**字段键名**：解析宽容，接受常见变体——`cve_id`/`cve`/`id`、`cvss`/`cvss_score`/`cvss-score`、`cvss_metrics`/`cvss-metrics`/`cvss_vector`、`product`/`affected`/`affected_products`、`reference`/`references`、`remediation`（含 `mitigation`/`mitigations`、`workaround`/`workarounds`）。仅 `cve_id` 必填且须匹配 `CVE-YYYY-NNNNN`。

**去重合并语义**：以 `cve_id` 为唯一键，逐条 upsert——

- 不存在 → 创建（计入「新建」）
- 已存在 → 仅补充空缺字段，不覆盖已有值；参考链接按 URL 去重追加；无字段可补则计入「跳过」
- 解析失败或 `cve_id` 非法 → 计入「失败」，单条异常不阻塞整批

**结果面板**：环形进度（总计 / 成功）+ 四段明细（新建 / 更新 / 跳过 / 失败）+ 失败详情列表。页面右上角「查看模板」打开抽屉，提供四种格式的完整模板，可一键复制。模板文件亦存放于 `templates/cve/` 目录。

## 7. 常见问题

### 7.1 新建 POC 时提示"名称已存在"

每个 POC 名称在当前来源下必须唯一。如果导入时出现此提示，系统会自动在名称后拼接哈希后缀以保证唯一性。

### 7.1.1 登录提示"登录尝试过于频繁"

系统按客户端 IP 对登录接口做固定窗口限流，防止暴力破解：默认 300 秒窗口内最多 5 次尝试。超出后（含正确密码）一律返回 429 并附带 `Retry-After` 响应头，提示剩余冷却秒数，窗口结束自动恢复。登录成功会立即清零失败计数，正常使用不受影响。

如需调整：在 `.env` / 部署环境变量中设置 `VULNSCOPE_LOGIN_RATE_LIMIT_ENABLED`、`VULNSCOPE_LOGIN_RATE_LIMIT_MAX_ATTEMPTS`、`VULNSCOPE_LOGIN_RATE_LIMIT_WINDOW`。生产环境建议保持开启。

### 7.2 表单构建模式无法切回

当格式为 `Pocsuite3` 或 `原始脚本` 时，仅支持源码模式。表单构建模式仅适用于 `Nuclei YAML` 和 `JSON` 格式。

### 7.3 标签关联后找不到

在 POC 详情页的「标签」字段中查看。也可以在标签管理页搜索该标签，查看关联的 POC 数量。

### 7.4 如何回退 POC 内容

每次保存内容会生成版本快照，版本历史为只读查看。如需回退，可手动复制历史版本内容覆盖当前版本。

### 7.5 为什么导入的 POC 显示"内容重复"

系统基于 SHA-256 内容哈希进行去重。如果导入的 POC 内容与已有 POC 完全相同，会被自动跳过。建议先确认是否为预期行为，如需强制导入，可在内容中写入注释后重新导入。

### 7.6 导入 CVE 时为何部分记录显示"跳过"

「跳过」表示该 `cve_id` 已存在且当前导入内容没有可补充的空缺字段（所有字段均已填）。系统采用「仅补缺、不覆盖」策略，避免覆盖手工录入的数据。如需强制覆盖，可先删除目标 CVE 再导入。

### 7.7 CVE 的 CVSS 评分与级别是否联动

两者独立存储，不自动推导。CVSS 评分为 0–10 的数值，严重级别为 info/low/medium/high/critical 的定性标签。导入或编辑时分别填写，详情页按级别对评分着色，但不会按评分自动改写级别。
